# Ирцийн төхөөрөмж холбох — алхам алхмаар

Ирцийг гурван аргаар бүртгэнэ. Бүгд нэг дор (`attendance_punches`) орж, өдрийн ирц
(ирсэн = эхний бүртгэл, тарсан = сүүлийнх) автоматаар тооцоологдоно.

| Арга | Хэзээ | Тохиргоо |
|---|---|---|
| Байршлаар (утас) | Ажилтан утаснаасаа | Админ → Салбарууд → засах → «Утсаар байршлаар ирц бүртгэхийг зөвшөөрөх» |
| 4370 · агент | ADMS-гүй төхөөрөмж (JDF200) | Ресепшний компьютерт агент суулгана — **3-р алхам** |
| Push · ADMS | ADMS дэмждэг төхөөрөмж (TX628) | Төхөөрөмж өөрөө серверт илгээнэ — **4-р алхам** |

---

## 0. Нэг удаа: серверт байршуулах

Ирцийн код одоогоор зөвхөн хөгжүүлэгчийн компьютерт байна. Салбаруудыг холбохоос өмнө:

1. Код commit хийгээд серверт байршуулна (ердийн дарааллаар).
2. Сервер дээр: `php artisan migrate --force` — ирцийн 6 шинэ migration орно.
   Ирцийн хуучин (утсаар бүртгэсэн) мэдээлэл автоматаар шинэ бүтэц рүү хуулагдана.
3. `php artisan schedule:run` cron ажиллаж байгаа эсэхийг шалгана (CallPro-д аль хэдийн
   ашиглагддаг) — төхөөрөмж тасарсан мэдэгдэл үүгээр 15 минут тутам шалгагдана.
4. Frontend build (`npm run build`) — HR → **Ирцийн төхөөрөмж** хуудас гарч ирнэ.
5. Push (ADMS) төхөөрөмж холбох бол **4.1**-ийг хийнэ.

Шалгах: `https://<домэйн>/hr/attendance/devices` нээгдэж байвал болсон.

## 1. Төхөөрөмж аль төрлийнх вэ

Төхөөрөмжийн цэсний **Comm. (通讯设置)** хэсгийг нээнэ:

- `Cloud Server Setting` / `ADMS` / `云服务设置` гэсэн мөр **байвал** → **Push** → 4-р алхам
- Зөвхөн `Ethernet/网络设置` болон `PC Connection/连接设置` байвал → **4370** → 3-р алхам

Мөн `System Info (系统信息)` цэснээс **Serial №**-ийг тэмдэглэж авна.

## 2. Агентын exe бэлдэх (нэг удаа, хөгжүүлэгчийн компьютер дээр)

Зөвхөн 4370 төхөөрөмжид хэрэгтэй.

1. `tools\attendance-agent\build.bat` дээр хоёр товшино (Python суусан компьютер дээр).
2. Бэлэн хавтас: **`tools\attendance-agent\dist\attendance-agent\`**
   ```
   attendance-agent.exe   ← агент (Python шаардлагагүй)
   install-task.bat       ← суулгах (хоёр товшино)
   install.ps1
   uninstall-task.bat     ← устгах
   README.txt             ← ресепшний ажилтанд зориулсан товч заавар
   ```
3. Энэ хавтсыг USB flash-д хуулна. Нэг хавтас бүх салбарт ашиглагдана — салбар бүрийн
   ялгаа нь зөвхөн `config.json` (3.3-д HR хуудаснаас авна).

`agent.py` өөрчлөгдвөл build.bat-ыг дахин ажиллуулж, салбаруудад шинэ exe-г солино
(`config.json`, `state.json`-д хүрэхгүй).

## 3. 4370 төхөөрөмж холбох (салбар бүрт)

### 3.1 Төхөөрөмжийн сүлжээ
1. Ресепшний компьютер дээр `cmd` → `ipconfig` → **IPv4 Address** (жишээ `192.168.10.25`)
   болон **Default Gateway** (жишээ `192.168.10.1`)-г харна.
2. Төхөөрөмжид ижил сүлжээнээс сул хаяг сонгоно, жишээ нь `192.168.10.201`.
   Сул эсэхийг `ping 192.168.10.201` — **хариу ирэхгүй** байх ёстой.
   Router-ийн DHCP муж (ихэвчлэн .100–.199) -аас **гадуур** сонгоно — эс тэгвээс router
   тэр хаягийг өөр утас/компьютерт өгч, төхөөрөмж «холбогдоогүй» болно.
3. Төхөөрөмж дээр `通讯设置 → 网络设置`:
   - DHCP → **OFF**
   - IP地址 → `192.168.10.201`
   - 子网掩码 → `255.255.255.0`
   - 网关地址 → `192.168.10.1`
4. `通讯设置 → 连接设置`: 通讯密码 (Comm key) = `0`.
5. Төхөөрөмжийг LAN кабелиар router/switch-д залгана.
6. Ресепшний компьютер дээр `ping 192.168.10.201` — **хариу ирэх** ёстой.

### 3.2 Системд бүртгэх
1. DentaSuite → HR → **Ирцийн төхөөрөмж** → **Төхөөрөмж нэмэх**.
2. Холболтын төрөл **4370 · агент**, Нэр (жишээ «Сансар — үүдний»), Салбар, IP хаяг
   (`192.168.10.201`), Порт `4370`, Comm key `0` → Хадгалах.
3. Шар хайрцагт **агентын тохиргоо** гарна → **Хуулах**.
   ⚠ Зөвхөн нэг удаа харагдана. Алдсан бол 🔑 товчоор шинийг үүсгэнэ — хуучин нь ажиллахаа болино.

### 3.3 Агент суулгах (ресепшний компьютер)
1. USB-ээс `attendance-agent` хавтсыг **`C:\DentaSuite\Attendance\`** болгож хуулна.
2. Notepad нээж 3.2-т хуулсныг буулгана → Save As → `C:\DentaSuite\Attendance\config.json`,
   «Save as type» = **All files** (`config.json.txt` болохгүй байх ёстой).
3. **`install-task.bat`** дээр хоёр товшино.
   - «Windows protected your PC» гарвал: More info → Run anyway.
4. Хэдэн секундэд **«Ирцийн агент — амжилттай»** цонх гарна: төхөөрөмжийн SN, хэрэглэгч ба
   бүртгэлийн тоо, «Сервертэй холбогдлоо ✓».
5. HR → Ирцийн төхөөрөмж хуудсанд төхөөрөмж **«Холбогдсон»** болж, хэрэглэгчид нь
   «Тааруулаагүй» табд гарч ирнэ → **5-р алхам**.

Анх суулгахад агент **өмнөх сарын 1-нээс хойшхи** бүртгэлийг л илгээнэ — төхөөрөмж олон жилийн
түүх хадгалдаг (Хороолол TX628 дээр 2018 оноос 36,000 бүртгэл). Илүү хуучин түүх хэрэгтэй бол
`config.json`-д `"since": "2025-01-01",` мөр нэмээд `state.json`-ийг устгана.

Агент Windows-д нэвтэрмэгц болон 5 минут тутам ажиллана. Компьютер шөнө унтрах нь асуудалгүй —
бүртгэл төхөөрөмж дотор хадгалагдаж, өглөө асахад татагдана. Агент төхөөрөмжийн логийг
хэзээ ч устгахгүй, өдөрт нэг удаа төхөөрөмжийн цагийг серверийн цагаар тохируулна.

Нэг салбарт нэг агент = нэг төхөөрөмж. Нэг салбарт хоёр төхөөрөмж байвал хөгжүүлэгчид хандана.

## 4. Push (ADMS) төхөөрөмж холбох

### 4.1 Нэг удаа: серверт `/iclock`-ийг HTTP-ээр нээх
Хуучин firmware **зөвхөн HTTP** (HTTPS биш) илгээдэг. 80 портын nginx блокт `/iclock/`-ийг
PHP руу оруулж, бусдыг HTTPS руу redirect хийнэ:

```nginx
server {
    listen 80;
    server_name yourdomain.mn;

    # ZKTeco ADMS — HTTPS дэмждэггүй төхөөрөмж
    location /iclock/ {
        root /var/www/dentalweb/public;
        try_files $uri /index.php?$query_string;
    }

    location = /index.php {
        root /var/www/dentalweb/public;
        # 443 блок дахь fastcgi тохиргоог яг хэвээр нь хуулна
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/php8.3-fpm.sock;
    }

    location / {
        return 301 https://$host$request_uri;
    }
}
```

Certbot-ийн үүсгэсэн 80 портын блокт `if ($host = ...) { return 301 https://... }` мөр байдаг —
тэр нь `location`-оос өмнө ажилладаг тул **заавал устгана**, эс тэгвээс `/iclock` ч шилжинэ.
`root`, `include`, `fastcgi_pass` мөрүүдийг 443 блокоос яг хэвээр нь хуулна. Дараа нь
`sudo nginx -t && sudo systemctl reload nginx`.

Cloudflare ашиглаж байгаа бол «Always Use HTTPS» нь `/iclock`-ийг эвдэнэ — DNS-only (саарал үүл)
дэд домэйн (жишээ `att.yourdomain.mn`) нээж, төхөөрөмжид тэр хаягийг өгнө.

Шалгах: `curl "http://yourdomain.mn/iclock/cdata?SN=TEST123"` → `GET OPTION FROM: TEST123`
гарвал болсон (дараа нь HR хуудаснаас «Шинэ төхөөрөмж (TEST123)»-ийг устгана).

### 4.2 Төхөөрөмж
1. `Comm. → Ethernet`: DHCP ON байж болно. DNS хоосон бол `8.8.8.8`.
2. `Comm. → Cloud Server Setting`:
   - Server mode → **ADMS**
   - Enable Domain Name → **ON**, Server Address → домэйн (жишээ `yourdomain.mn`)
   - Server Port → **80**
   - Enable Proxy Server → **OFF**
3. Төхөөрөмжийг дахин асаана.

### 4.3 Системд идэвхжүүлэх
1. HR → Ирцийн төхөөрөмж хуудсанд **«Шинэ төхөөрөмж (SN)»** шар товчтой гарч ирнэ
   (1-р алхамд тэмдэглэсэн Serial-тай таарч байгааг шалгана).
2. Товчийг дарж Нэр, Салбарыг бөглөөд «Идэвхтэй» → Хадгалах.
3. Идэвхжүүлэхээс өмнөх бүртгэл алга болохгүй — төхөөрөмж өөртөө хадгалаад дахин илгээнэ.

Анхаар: зарим firmware дээр ADMS асаахад 4370 (PC Connection) хаагддаг.

## 5. PIN ↔ ажилтан тааруулах (төхөөрөмж бүрт нэг удаа)

Төхөөрөмж дээрх ID системийн ажилтны дугаартай (`EMP-0012`) **таарах албагүй** — хуруу дахин
бүртгэх шаардлагагүй. Систем PIN-ээр таахгүй (буруу хүнд ирц бичигдэхээс сэргийлнэ).

1. HR → Ирцийн төхөөрөмж → **«Тааруулаагүй»** таб.
2. Төхөөрөмж дээрх нэр системийнхтэй таарвал (Bilguun ↔ Билгүүн, B.Saraa ↔ Б. Сараа) **санал**
   гарна → жагсаалтыг нэг харчихаад **«Санал болгосныг батлах»**.
3. Үлдсэнийг жагсаалтаас гараар сонгоно (тухайн салбарын ажилчид эхэндээ).
   Ижил нэртэй хоёр ажилтан байвал санал гарахгүй — гараар сонгоно.
4. Тааруулмагц тухайн PIN-ийн **өмнөх бүх бүртгэл** ирцэд орно. Буруу тааруулснаа засахад
   ирц зөв ажилтан руу шилжинэ.

Шинэ ажилтныг төхөөрөмж дээр бүртгэсний дараа агент дараагийн ажиллалтаар хэрэглэгчийн
жагсаалтыг илгээнэ → «Тааруулаагүй» табд гарна → тааруулна.

**Ажилтан ажлаас гарвал** төхөөрөмжөөс нь устгана. Түүний PIN-ийг шинэ хүнд олгосон ч систем
ирцийг гарсан хүнд бичихгүй — идэвхгүй ажилтны PIN дээр шинэ бүртгэл ирмэгц тааруулалтыг
салгаж «Тааруулаагүй» руу гаргана (хуучин түүх нь хэвээр).

JDF200-ийн нэр эвдэрсэн харагдвал `config.json`-ийн `device` хэсэгт `"encoding": "gbk"` нэмнэ.

## 6. Төхөөрөмжийн зөвлөмж тохиргоо

- **Давхар дарах хугацаа** (`重复确认时间` / Duplicate Punch Period): нэг хүн энэ хугацаанд дахин
  дарвал төхөөрөмж **бүртгэлдээ хадгалахгүй**. JDF200 дээр 60 минут байсан. Ажлын үед 60 хэвээр
  байж болно; туршилтын үед түр 1 болгоно.
- **Олон дарах:** ирэхдээ ч, тарахдаа ч 2-3 дарсан бол систем 5 минутын доторх дарсныг нэг гэж
  үзээд **эхний уншуулсан** цагийг авна (төхөөрөмжийн тохиргооноос үл хамааран).
- Ирсэн/тарсан товч (`~ShowState`) хэрэггүй — систем өдрийн эхний ба сүүлийн бүртгэлээр тооцно.
- **Санах ой:** JDF200 50,000 бүртгэл хадгална, дүүрмэгц шинэ бүртгэл авахаа больдог. HR хуудсанд
  төхөөрөмж бүрийн дүүргэлт харагдаж, 80%-иас дээш бол анхааруулга гарна → бүх бүртгэл системд
  орсныг шалгаад төхөөрөмжийн `数据管理` цэснээс хуучин бүртгэлийг устгана.

## 7. Өдөр тутмын ажил (HR)

**Хуруу дарахаа мартвал** — HR → Ирцийн бүртгэл:
- Тухайн мөр дээр дарна → тэр өдрийн бүх бүртгэл (төхөөрөмж, утас, гараар) харагдана →
  «Гараар нэмэх» хэсэгт ирсэн/тарсан цаг + **шалтгаан** бичээд Хадгалах.
- Тэр өдөр огт бүртгэлгүй бол толгойн **«Ирц нэмэх»** товч → ажилтан, огноо сонгоно.
- Төхөөрөмжийн бүртгэл хэзээ ч устахгүй — нэмэлт бүртгэл үүсч, жагсаалтад ✎ дүрстэй харагдана.
  Хэн, хэзээ, яагаад нэмсэн нь хадгалагдана. Буруу нэмснээ 🗑 товчоор устгана.

**Мэдэгдэл** (хонх → «Ирц» таб):
- Хуваарьтай ажилтан хоцорч ирвэл.
- Төхөөрөмж **ажлын цагаар 1 цагаас дээш** холбогдохгүй бол (нэг тасралтад нэг удаа).
  Ажлын цаг нь Админ → Дуудлага хэсгийн гараг бүрийн ажлын цагийн тохиргоог ашиглана.

- [ ] Хэрэв зөвхөн хурууны хээгээр бүртгэх бол Админ → Салбарууд → байршлын checkbox-ыг унтраасан

## Асуудал шийдэх

| Шинж тэмдэг | Шалтгаан / шийдэл |
|---|---|
| Төхөөрөмж «Холбогдоогүй» | 4370: ресепшний компьютер асаалттай эсэх, `agent.log`. Push: `/iclock` HTTP-ээр нээгдэж байгаа эсэх (4.1) |
| Суулгах үед «config.json олдсонгүй» | Файл `config.json.txt` болж хадгалагдсан — File Explorer → View → File name extensions асаагаад нэрийг засна |

| `agent.log`-д «(409)» | Энэ токен өөр төхөөрөмжийнх — `config.json`-ийн `ip` зөв төхөөрөмж рүү заасан эсэх |
| `agent.log`-д «TimeoutError» / холбогдохгүй | Төхөөрөмжийн IP өөрчлөгдсөн эсвэл кабель салсан — `ping <IP>` |
| Хоёр дахь дарсан нь орж ирэхгүй | Давхар дарах хугацаа (6-р хэсэг) — тэр хугацаа өнгөртөл төхөөрөмж хадгалахгүй |
| Шинэ ажилтны ирц орохгүй, «Тааруулаагүй»-д хуучин нэртэй PIN гарсан | Ажлаас гарсан хүний PIN-ийг шинэ хүнд олгосон — шинэ хүнтэй тааруулна (5-р алхам) |
| Санах ой 80%+ анхааруулга | 6-р хэсэг — системд орсныг шалгаад төхөөрөмж дээрх хуучин бүртгэлийг устгана |
| Бүртгэл ирцэд харагдахгүй | «Тааруулаагүй» табд PIN байгаа эсэх (5-р алхам) |
| Ажилтан хуруу дарахаа мартсан | HR → Ирцийн бүртгэл → мөр дээр дарж гараар нэмнэ (7-р хэсэг) |
| «Ирцийн төхөөрөмж холбогдохгүй» мэдэгдэл | Ресепшний компьютер асаалттай эсэх, `agent.log`; push бол сүлжээ |
| Цаг зөрүүтэй анхааруулга | Агент өдөрт нэг удаа тохируулна; push төхөөрөмжийн цагийг гараар шалгана |

## USB .dat (сүлжээ ажиллахгүй үеийн нөөц)
Төхөөрөмж дээр `U盘管理` (USB) → ирцийн бүртгэл татах → flash-д `attlog.dat` гарна.
HR → Ирцийн төхөөрөмж → тухайн төхөөрөмжийн USB дүрс → файлаа сонгоно. Давхардахгүй.
